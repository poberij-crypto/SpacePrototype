# Planetary flight implementation plan

> **For agentic workers:** Use superpowers:executing-plans, inline implementation.

**Goal:** Deliver Android 0.9.0 with reversible planetary landing loop and negative thrust.
**Architecture:** PlanetFlight owns transition/local-flight state, lazy scene loading and snapshot validation. PlanetRegion owns terrain geometry/height/sky; PlanetUI owns scene-specific controls, status and transition cover. Existing mission, snapshot, map and main delegate through those APIs.
**Tech Stack:** Godot 4.5.1, GDScript, Android ARM64.
**Spec:** ../specs/2026-11-03-planet-design.md

## Global constraints

- Preserve package org.dmitry.spaceprototype.ui, test signing key, sensor orientation, credits/cargo/upgrades and snapshots 1–3.
- New snapshot v4 allows throttle [-0.3,1]. Old versions retain their original bounds.
- Reverse control reaches -0.3 through -0.2, then stops at zero when increasing toward forward thrust; no negative plume scale.
- Save loading/transition/landed states without teleporting goods to another trading station.

## Review focus

- Save and restore during each transition and on ground without duplicate rewards or loss of cargo.
- Pausing, focus changes, touch release and orientation changes clear vertical and throttle-related held inputs.
- Unsafe landing (height, slope, speed), ground impact, region edge and orbit exit gates.
- Full planetary cycle from both stations; existing contracts unaffected.
- HUD/map fit portrait, landscape and foldable aspect ratios; old snapshots still validate.
